# 猫叔的游戏知识库：部署说明

写给接手部署的工程师。照着做就能把网站和 MCP 服务部署起来，不需要了解内容是怎么制作的。

项目主页：<https://github.com/mmlong818/game-mechanism-library>

> **从 GitHub 仓库直接看到这份说明的读者请注意**：这份说明是随“部署包”一起发的，文中的路径按部署包的目录写。在本仓库里对应关系是：
> - `site/` = 在仓库根目录运行 `npm ci && npm run build` 后得到的 `dist/`
> - `site-src/` = 仓库根目录
> - `mcp/` = 仓库里的 `mcp/`（需要先 `npm ci && npm run build` 得到 `dist/`）
> - `examples/` = 仓库里的 `docs/examples/`
>
> 部署包已经构建好、解压就能用；如果拿到了部署包，按包里的路径照做即可。

## 1. 这个包是什么

“猫叔的游戏知识库”是一个给游戏设计者查阅的资料站：机制、世界观、体验三个卡片库，加一本《RPG设计七卷书》。它有两种用法：人在网站上看；AI 工具通过 MCP 服务来查。

包里有这些东西：

| 路径 | 是什么 |
|---|---|
| `部署说明.md` | 本文件 |
| `site/` | 已经构建好的静态网站，整个目录上传就能用。里面的 `data/` 是内容（“发布包”），`site-config.json` 是部署后可以直接改的站点配置 |
| `site-src/` | 网站源码（Vite + React + TypeScript）。只有要改页面时才用得到 |
| `mcp/` | MCP 服务的源码和已经编译好的 `dist/`，含 `Dockerfile`、`docker-compose.yml`、`.env.example` |
| `examples/` | Nginx 配置示例（静态站、反向代理 MCP）、systemd 服务文件示例、AI 工具配置示例 |
| `LICENSE-CONTENT.md`、`LICENSE-CODE.md` | 内容和代码各自的授权 |
| `VERSION.json`、`SHA256SUMS.txt` | 版本信息和全部文件的校验值 |

各部分的关系：

```
                 ┌──────────────────────────────┐
  访客的浏览器 ──▶│ 静态网站 site/                │
                 │   index.html、assets/、covers/ │
                 │   site-config.json            │
                 │   data/current.json  ─┐       │  current.json 写着当前用哪个发布编号
                 │   data/release/<编号>/ ◀┘      │  发布包：全部内容，只读的 JSON 文件
                 └──────────────▲───────────────┘
                                │ 通过 HTTP 读同一份发布包（也可以改成读本地目录）
                 ┌──────────────┴───────────────┐
  访客的 AI 工具 ▶│ MCP 服务 mcp/                 │  六个只读工具，无状态
                 │   公开网址版 dist/http.js      │  ← 放在反向代理后面，对外是 https://…/mcp
                 │   本地安装版 dist/stdio.js     │  ← 由访客自己的 AI 工具在本机启动
                 └──────────────────────────────┘
```

要点：

- 网站是纯静态的，没有后端。页面打开后读 `data/current.json`，再按里面的发布编号读 `data/release/<编号>/` 下的文件。
- MCP 服务自己不带内容，读的是同一份发布包。推荐让它直接读已部署网站上的那一份（给它网站地址即可），这样只需要维护一份数据，网站和 MCP 也可以放在不同的机器上。
- 网站的“接入 AI”页告诉访客怎么把 MCP 接到自己的 AI 工具里；页面上显示的网址来自 `site-config.json`。

只部署网站、不部署 MCP 也可以，但要知道：“接入 AI”页在没填配置时显示的是占位地址和占位命令（见第 5 节），访客照着做是接不通的。

## 2. 环境要求

- **网站**：任何能放静态文件的地方（Nginx、对象存储加 CDN、GitHub Pages、Cloudflare Pages 等）。不需要 Node。
- **MCP（公开网址版）**：一台能常驻运行进程的服务器；Node.js 20 或更高（推荐 22）；或者 Docker。还需要一个反向代理（Nginx、Caddy 等）、一个域名和 TLS 证书。
- **重新构建网站**（可选）：Node.js 22 或更高。
- 内存：MCP 进程启动后约 90～100 MB。磁盘：`site/` 约 16 MB，其中发布包约 13 MB。

## 3. 部署网站

### 3.1 通用做法

把 `site/` 目录里的全部内容原样上传到站点目录。可以放在域名根目录（`https://example.com/`），也可以放在任意子路径（`https://example.com/tools/library/`）；页面里的脚本、样式、数据、封面图都用相对地址加载，不需要为路径重新构建。

注意三点：

1. **放在子路径时，访问地址要以斜杠结尾**（`/tools/library/`，不是 `/tools/library`）。绝大多数服务器会自动把后者重定向到前者；如果你的服务器不会，请加一条重定向，否则页面会找不到脚本。
2. **`.json` 文件要能被正常访问**，响应类型应为 `application/json`。个别托管环境默认不提供 `.json` 或会拦截它，需要放开。
3. **`data/current.json` 和 `site-config.json` 不要长时间缓存**（建议 `Cache-Control: no-cache`），否则更新内容或改配置后访客要等缓存过期才看得到。`assets/` 下的文件名带内容哈希，`data/release/<编号>/` 下的文件发布后不再变，这两处可以长期缓存。

页面用的是 hash 路由（地址形如 `…/#/c/mechanism/combat/…`），服务器不需要配任何地址改写。

页面的字体从 Google Fonts 加载（`fonts.googleapis.com`）。访问不到时页面自动改用系统字体，功能不受影响，只是字形不同。

### 3.2 Nginx

`examples/nginx-site.conf` 是一份可以直接改的站点配置，里面有根目录部署和子路径部署两种写法，以及上面说的缓存设置。把域名、证书路径、站点目录换成你的，放进 Nginx 的站点配置目录，`nginx -t` 检查后重载。

### 3.3 托管平台

- **GitHub Pages**：把 `site/` 的内容作为要发布的目录（推到发布分支的根目录，或在 Actions 里把它作为 Pages 的产物上传）。项目站点的地址是 `https://<用户>.github.io/<仓库名>/`，属于子路径部署，直接可用。仓库根目录放一个空的 `.nojekyll` 文件，避免平台对文件做额外处理。
- **Cloudflare Pages**：新建项目，选择“直接上传”，把 `site/` 目录拖进去即可；不需要构建命令。如果从源码仓库构建，构建命令 `npm ci && npm run build`，输出目录 `dist`，Node 版本设为 22。
- **对象存储加 CDN**（S3、OSS、COS 等）：上传 `site/` 的全部内容，把默认首页设为 `index.html`，并确认 `.json` 的响应类型和上面的缓存设置。

### 3.4 部署后的验证清单

用浏览器打开站点地址，逐项确认：

- [ ] 首页直接显示机制库的三栏界面：左栏是带缩略图的主题，中栏是卡片名称，右栏是一张卡的全文。
- [ ] 点顶栏的“世界观”“体验”，同样能看到卡片。
- [ ] 点顶栏的“RPG设计七卷书”，先是书名页和“前言”；左侧栏的目录按卷一到卷七分组（每卷可以折叠），最后是附录；页尾的“下一章”能翻页。
- [ ] 顶部搜索框输入“牌组”有结果；输入“账城”能搜到书里的前言和章节。
- [ ] 打开任意一张卡片，复制浏览器地址，在新标签页里打开，仍然是这张卡；刷新页面不丢。
- [ ] 顶栏的“接入 AI”能打开，代码块右上角的“复制”按钮可用；最右侧的小字“版权”能打开，旁边的“GitHub”在新窗口打开项目仓库。
- [ ] 浏览器开发者工具的控制台里没有红色的报错，网络面板里没有 404。

## 4. 部署 MCP（公开网址版）

MCP 服务是一个 Node 进程，默认监听 `127.0.0.1:8787`。对外的地址由反向代理提供，最终给访客的是形如 `https://mcp.example.com/mcp` 的网址。

**服务自己不做 TLS，也不做限流，必须放在反向代理后面。** 它只读、无状态、不存任何用户数据、不需要登录，可以随时重启。

### 4.1 先决定数据从哪里来

三种方式任选一种，用环境变量设置：

| 方式 | 环境变量 | 适合 |
|---|---|---|
| 跟随网站（推荐） | `GDL_SITE_URL=https://example.com`（网站的地址，子路径也行） | 网站已经部署好。MCP 读 `<网站地址>/data/current.json`，之后每 5 分钟再看一次，网站换了发布包它自动跟着换，不用重启 |
| 固定某个发布编号 | `GDL_SITE_URL=…` 加 `GDL_RELEASE_ID=2026-11-13.2` | 想让 MCP 停在某个版本上，不随网站变 |
| 本地目录 | `GDL_RELEASE_DIR=/srv/…/site/data/release/2026-11-13.2` | MCP 和网站文件在同一台机器上，或者不想让 MCP 依赖网络 |

用网站地址时，文件按需下载并缓存在本机（下载后按校验值核对），网站暂时连不上也能靠缓存启动。全部环境变量的说明在 `mcp/.env.example` 和 `mcp/README.md` 里。

### 4.2 方式一：用 Node 直接运行

```sh
# 1. 把包里的 mcp/ 目录放到服务器上，例如 /opt/game-design-library/mcp
cd /opt/game-design-library/mcp

# 2. 安装依赖并编译（包里已经带了编译好的 dist/，这一步的编译可以省，但依赖必须装）
npm ci
npm run build

# 3. 先在前台试跑一次
GDL_SITE_URL=https://example.com node dist/http.js
```

看到下面这样的三行就是起来了（按 Ctrl+C 停掉）：

```
[game-design-library] 已加载发布包 2026-11-13.2（约定 1.0）：mechanism 1384，world 132，experience 148，book 36；来源 https://example.com/data/release/2026-11-13.2
[game-design-library] 允许的浏览器来源：无（不带 Origin 的请求不受影响）；Host 检查：关；每 300 秒检查一次网站的 current.json
[game-design-library] listening http://127.0.0.1:8787/mcp
```

然后做成系统服务。`examples/game-design-library-mcp.service` 是 systemd 的服务文件示例，`examples/mcp.env` 是它读的环境变量文件示例：

```sh
sudo useradd --system --home /var/lib/gdl-mcp --create-home --shell /usr/sbin/nologin gdl-mcp
sudo mkdir -p /etc/game-design-library
sudo cp examples/mcp.env /etc/game-design-library/mcp.env        # 改里面的 GDL_SITE_URL 等
sudo cp examples/game-design-library-mcp.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now game-design-library-mcp
systemctl status game-design-library-mcp
journalctl -u game-design-library-mcp -n 20
```

服务文件里的安装路径（`/opt/game-design-library/mcp`）和 `node` 的路径（`/usr/bin/node`）请按实际情况改。

### 4.3 方式二：用 Docker

```sh
cd mcp
cp .env.example .env          # 改里面的 GDL_SITE_URL 等
docker compose up -d --build
docker compose ps             # 状态应为 healthy
```

镜像是多阶段构建，以非 root 用户运行，根文件系统只读（缓存放在 `/tmp` 的内存盘里），端口只绑在宿主机的 `127.0.0.1:8787` 上，仍然需要宿主机上的反向代理对外提供 HTTPS。

> **说明：这份 `Dockerfile` 和 `docker-compose.yml` 在交付前没有实际构建验证过**（打包的机器上没有可用的 Docker 守护进程）。写法是常规的，但第一次构建时如果报错，请以报错为准调整；用 Node 直接运行的方式是完整验证过的。

### 4.4 反向代理、TLS、限流

`examples/nginx-mcp.conf` 是反向代理的示例，包含：

- HTTPS（把证书路径换成你的；80 端口跳转到 443）；
- 限流（每个来源地址每秒 10 个请求，突发 20；按需要调整）；
- 请求体上限 1 MB（和服务自身的上限一致）；
- 关闭代理缓冲和缓存（`proxy_buffering off` 等），流式响应不会被攒着不发；
- 只转发 `/mcp` 和 `/health` 两个地址。

MCP 可以用单独的域名（`https://mcp.example.com/mcp`），也可以挂在网站域名的某个路径下；示例里两种写法都有。

### 4.5 浏览器来源（Origin）白名单

这一项只影响“浏览器里的网页直接调用 MCP”的情况：

- Claude Code、Cursor 这类本机工具，以及各家 AI 服务从它们的服务器发起的连接，请求里不带 `Origin`，**不受白名单影响，默认就能用**。
- 浏览器里的网页调用时会带 `Origin`。默认白名单是空的，所以一律返回 403。如果确实需要让某个网页直接调用（例如在线的 MCP 调试工具），把它的来源加进 `GDL_ALLOWED_ORIGINS`，多个用逗号分开，例如 `GDL_ALLOWED_ORIGINS=https://example.com,https://tools.example.com`。写 `*` 表示全部放行，一般没有必要。

另有 `GDL_ALLOWED_HOSTS`（检查 `Host` 请求头），默认不检查。如果设了，反向代理必须把原始的 `Host` 传给后端（示例配置里已经有 `proxy_set_header Host $host;`）。

### 4.6 健康检查

`GET /health` 返回当前的发布编号，可以给负载均衡或监控用：

```sh
curl -s https://mcp.example.com/health
# {"ok":true,"release":"2026-11-13.2","contract_version":"1.0","mcp":"/mcp"}
```

### 4.7 部署后的验证

最省事的是用包里的冒烟脚本直接测线上地址（在装过依赖的 `mcp/` 目录里运行，任何一台能上网的机器都行）：

```sh
node scripts/smoke-http.mjs --url https://mcp.example.com/mcp
```

它会依次做初始化、列出六个工具、取版本信息、搜索、取一张卡、查健康检查、检查 Origin 白名单，每项打印“通过”或“失败”，最后一行是“HTTP 入口全部通过”。

没有 Node 的机器上可以用 `curl` 发一个初始化请求：

```sh
curl -s https://mcp.example.com/mcp \
  -H 'content-type: application/json' \
  -H 'accept: application/json, text/event-stream' \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"curl","version":"0"}}}'
```

返回的 JSON 里有 `"serverInfo":{"name":"game-design-library",…}` 就是通的。

最后在真实的 AI 工具里接一次（见第 6 节的命令），问它“猫叔的游戏知识库里有哪几个库”。

## 5. 把网站的“接入 AI”页点亮

“接入 AI”页始终按 MCP 已经上线的样子写出完整的接法。**不填配置时，页面上显示的是占位内容**：地址是 `https://你的域名/mcp`，命令是 `claude mcp add --transport http game-design-library https://你的域名/mcp`，本地安装一节用的是从 `repo_url` 的仓库 `git clone` 的写法；占位内容下方各有一行小字“地址以上线后公布的为准”“下载地址以上线后公布的为准”。部署好 MCP 之后，把 `mcp_url` 填上（有本地安装包的下载地址的话把 `local_download_url` 也填上），页面上的地址和命令就变成真实的，那两行小字随之消失。

编辑已部署网站根目录下的 `site-config.json`（和 `index.html` 在同一层）。改完保存即可，不用重新构建，访客刷新页面就生效。

```json
{
  "mcp_url": "https://mcp.example.com/mcp",
  "mcp_name": "game-design-library",
  "local_download_url": "",
  "contact": "",
  "repo_url": "https://github.com/mmlong818/game-mechanism-library"
}
```

| 字段 | 作用 | 留空时 |
|---|---|---|
| `mcp_url` | 公开的 MCP 网址（第 4 节部署好的那个，以 `/mcp` 结尾）。填了，页面的“接法一”显示这个网址，以及用它拼出的 Claude Code 添加命令和通用的 JSON 配置 | 显示占位地址 `https://你的域名/mcp` 和相应的占位命令，并注明以上线后公布的为准 |
| `mcp_name` | 访客在 AI 工具里看到的服务名，只能用字母、数字、连字符和下划线 | 用 `game-design-library` |
| `local_download_url` | 本地安装版的下载地址（一个能下载到 `mcp/` 目录压缩包的网址，见第 6 节）。填了，页面的“接法二”第 2 步写“下载安装包并解压” | 第 2 步改用从 `repo_url` 的仓库 `git clone` 的写法，并注明下载地址以上线后公布的为准 |
| `contact` | 作者的联系方式：邮箱、网址或一句话。显示在“版权”页“想商用或改编”一段 | 那一段改为引导到 `repo_url` 的仓库提 issue；`repo_url` 也为空时只写“请联系作者。” |
| `repo_url` | 项目的 GitHub 仓库地址。顶栏最右侧的“GitHub”链到这里 | 写成空字符串时顶栏不显示“GitHub”。整个字段不写时用默认的仓库地址 |

三个网址字段都必须是 `http://` 或 `https://` 开头的完整网址，否则按没填处理。这个文件缺失、写坏了（不是合法的 JSON），页面都不会出错，只是按全部留空显示（`repo_url` 按默认的仓库地址）。改完建议用 `python -m json.tool site-config.json` 或任何 JSON 校验工具检查一下格式。

## 6. 本地安装版：给使用者的说明

下面这一小节可以原样转发给最终用户。你需要先给他们一个能下载到 `mcp/` 目录的地方（例如把包里的 `mcp/` 单独打成一个压缩包放到网上），并把其中的 `https://example.com` 换成网站的实际地址。

> **在自己的电脑上安装“猫叔的游戏知识库”的 AI 接入程序**
>
> 1. 安装 Node.js 20 或更高版本（<https://nodejs.org/>）。
> 2. 下载安装包并解压。下面用 `<解压位置>` 表示解压后的 `mcp` 目录所在的位置。
> 3. 在 `mcp` 目录里打开终端，依次运行：
>
>    ```
>    npm ci
>    npm run build
>    ```
>
> 4. 把它加进你的 AI 工具。数据来源有两种配法，选一种：
>
>    **配法一：从网站读取（推荐）。** 内容跟着网站更新，重启 AI 工具后就是最新的；读过的内容会缓存在本机。
>
>    Claude Code：
>
>    ```
>    claude mcp add game-design-library -- node "<解压位置>/mcp/dist/stdio.js" --site-url https://example.com
>    ```
>
>    其他工具（Claude 桌面版、Cursor 等），在它的 MCP 配置文件里加：
>
>    ```json
>    {
>      "mcpServers": {
>        "game-design-library": {
>          "command": "node",
>          "args": ["<解压位置>/mcp/dist/stdio.js", "--site-url", "https://example.com"]
>        }
>      }
>    }
>    ```
>
>    **配法二：读本机上的一份数据。** 不联网也能用。需要另外拿到一个“发布包”目录（里面有 `manifest.json`），把上面的 `--site-url https://example.com` 换成 `--release-dir "<发布包目录>"`。以后内容更新时要自己换成新的目录。
>
> 5. 重启 AI 工具，问它一句“猫叔的游戏知识库里有哪几个库”。它答得出各库的卡片数量，就说明接通了。
>
> Windows 上的路径在 JSON 里请用正斜杠（`C:/tools/mcp/dist/stdio.js`）。这个程序只读取资料，不会改动你电脑上的其他文件，也不上传任何东西。内容的作者是猫叔，可以阅读和原样分享，不得商用和改编。

`examples/ai-tools/` 下有这些配置的独立文件，可以直接拿去改。

## 7. 以后怎么更新内容

内容以“发布包”为单位更新。每次更新你会拿到一个新的目录，名字就是发布编号（例如 `2026-12-01.1`），里面有 `manifest.json` 和 `collections/`。发布包生成后不再修改，所以更新就是“加一个目录，改一个指针”。

**更新：**

1. 把新目录整个上传到网站的 `data/release/<新编号>/`（和现有的编号目录并列）。先传完，再做下一步。
2. 把网站的 `data/current.json` 改成 `{"release":"<新编号>"}`。
3. 打开网站看一眼（第 3.4 节的清单）。访客刷新页面后看到的就是新内容。
4. MCP：
   - 用“跟随网站”方式的（只设了 `GDL_SITE_URL`）：不用动。最迟 5 分钟后自动切换，日志里会有一行“网站换了发布包，已切换到…”。想立刻生效就重启服务。
   - 固定了编号的（设了 `GDL_RELEASE_ID`）或用本地目录的（`GDL_RELEASE_DIR`）：把环境变量改成新的编号或目录，重启服务（`sudo systemctl restart game-design-library-mcp`，或 `docker compose up -d`）。
5. `curl -s https://mcp.example.com/health` 确认 `release` 是新编号。

**回退：** 旧的发布包目录不要急着删。出了问题，把 `data/current.json` 改回上一个编号即可，MCP 同样自动跟随（或把环境变量改回去并重启）。确认新包稳定后，再删掉不需要的旧目录；每个约 13 MB。

**核对新包（可选）：** 在 `site-src/` 里把新目录放进 `public/data/release/`、改好 `public/data/current.json`，运行 `npm ci && npm run check:data`，它会检查索引、正文、链接和封面图是否齐全。如果新包里多了新的分组，这个检查会提示缺封面图（`covers/<库>-<分组>.jpg`）；缺图不影响使用，只是该分组前面没有缩略图。

**改页面本身：** 在 `site-src/` 里改代码，`npm ci && npm run build`，把生成的 `dist/` 当作新的 `site/` 上传（`dist/` 里同样带着 `data/` 和 `site-config.json`，上传时注意不要用源码里的空白 `site-config.json` 覆盖线上已经填好的那份）。

## 8. 安全与运维

- **全部只读。** 网站没有后端，也没有表单提交。MCP 的六个工具都只读，没有任何写入或执行类的工具。
- **不存用户数据。** 没有账号、没有 Cookie、没有统计脚本。MCP 不保存访客的查询内容。
- **MCP 写磁盘的只有一处**：用网址作数据来源时的缓存目录（默认是运行用户的缓存目录，可用 `GDL_CACHE_DIR` 改）。缓存不可写也能运行，只是每次启动都要重新下载。
- **日志**（都写到标准错误，systemd 下进 journal，Docker 下用 `docker compose logs` 看）：启动时一行已加载的发布包和数据来源，一行访问控制设置，一行监听地址；换发布包时一行；出错时一行。默认不记录每个请求；把 `GDL_ACCESS_LOG` 设为 `1` 后每个请求记一行，只有方法、路径、状态码和耗时，没有请求内容和来源地址。需要按来源地址排查时看反向代理的访问日志。
- **资源占用**（实测）：MCP 进程启动后常驻内存约 90～100 MB，启动时把四个库的索引读进内存，卡片正文按分组在第一次用到时读入；单次查询耗时在毫秒级，CPU 占用可以忽略。发布包约 13 MB、66 个文件；`site/` 总共约 16 MB。
- **对外暴露面**：只需要对外开放反向代理的 443（和用于跳转的 80）。MCP 的 8787 端口保持只在本机监听。
- **升级 Node 或依赖**后，重新 `npm ci && npm run build`，再跑一遍第 4.7 节的冒烟脚本。

### 常见问题

| 现象 | 多半是因为 | 怎么办 |
|---|---|---|
| 网站打开是白页，控制台里脚本或样式 404 | 子路径部署时访问的地址没有以斜杠结尾；或 `assets/` 没传全 | 加上结尾的斜杠或配重定向；对照 `SHA256SUMS.txt` 检查文件 |
| 页面显示“这一页没有加载出来” | `data/current.json` 或发布包里的文件取不到（404、被拦截、响应类型不对），或 `current.json` 里的编号和目录名对不上 | 在浏览器里直接打开 `<站点>/data/current.json` 和 `<站点>/data/release/<编号>/manifest.json` 看能不能取到 |
| 更新了内容，访客看到的还是旧的 | `current.json` 被 CDN 或浏览器缓存了 | 给它设 `Cache-Control: no-cache`，并刷新 CDN 缓存 |
| “接入 AI”页还是占位地址 `https://你的域名/mcp` | `site-config.json` 没改对位置、不是合法 JSON、网址不是 `http(s)://` 开头，或被缓存 | 在浏览器里直接打开 `<站点>/site-config.json` 看内容 |
| MCP 启动失败：“没有指定发布包的来源” | 环境变量没传进进程 | 检查 systemd 的 `EnvironmentFile` 或 Docker 的 `.env` |
| MCP 启动失败：“请求 …/data/current.json 失败” | `GDL_SITE_URL` 写错，或服务器访问不到网站 | 在服务器上 `curl <网站地址>/data/current.json`；注意子路径部署时网站地址要带上子路径 |
| AI 工具连不上，反向代理返回 502 | MCP 进程没在运行，或端口不对 | `systemctl status`、`curl http://127.0.0.1:8787/health` |
| 请求返回 403“不允许的来源（Origin）” | 调用方是浏览器里的网页，它的来源不在白名单里 | 需要放行就加进 `GDL_ALLOWED_ORIGINS` 并重启 |
| 请求返回 403“不允许的 Host” | 设了 `GDL_ALLOWED_HOSTS`，但代理没把原始 Host 传过来，或名单里没写对外的域名 | 加 `proxy_set_header Host $host;`，或清空 `GDL_ALLOWED_HOSTS` |
| 请求返回 405 | 用 GET 访问了 `/mcp` | 正常现象：这个端点只接受 POST。健康检查请用 `/health` |
| 请求返回 429 或 503 | 触发了反向代理的限流 | 调整示例配置里的 `rate` 和 `burst` |

## 9. 六个 MCP 工具

| 工具 | 作用 | 必填参数 |
|---|---|---|
| `list_collections` | 列出有哪些库、各多少条、各自的分组 | 无 |
| `search` | 按关键词搜索条目，返回名称和一句话摘要（不含正文）；书的章节同时搜正文。可选 `collection`、`group`、`tag`、`limit`、`offset` | `query` |
| `get_entry` | 按 id 取一个条目的全文 | `id` |
| `list_group` | 列出某个分组下的条目。可选 `limit`、`offset` | `collection`、`group` |
| `get_links` | 查一个条目提到了哪些条目、又被哪些条目提到 | `id` |
| `get_library_info` | 发布编号、各库条数、数据来源、内容的授权说明 | 无 |

条目的 id 形如 `mechanism/remove-cards-to-thin-deck`（库名、斜杠、库内 id）。四个库的 id 分别是 `mechanism`（机制）、`world`（世界观）、`experience`（体验）、`book`（书）。
