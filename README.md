# 猫叔的游戏知识库（网站）

猫叔整理的游戏设计卡片站，纯静态，部署在 GitHub Pages。技术栈是 Vite + React + TypeScript，没有后端。

网站本身不含卡片内容，只读“发布包”。发布包的格式由资料库仓库里的 `content/design-library/CONTRACT.md` 约定（约定版本 1.x）。目前有三个卡片库：机制、世界观、体验；另有一个“书”库，按章节收整本书的正文。

## 目录

- `public/data/current.json`：当前用哪个发布包，例如 `{"release":"2026-11-13.2"}`。
- `public/data/release/<发布编号>/`：发布包原样复制进来，不要改里面的文件。
- `public/covers/`：卡片库左栏分组名前面的像素封面缩略图，512×512 的 jpg，每个分组一张，文件名是 `<库>-<分组 slug>.jpg`。
- `public/site-config.json`：站点配置，部署后可以直接改，不用重新构建（见下面“站点配置”一节）。
- `src/`：页面代码。`config.ts` 读站点配置，`data.ts` 读发布包，`router.ts` 是 hash 路由，`browse.tsx` 是卡片库的三栏界面，`entry.tsx` 是其中右栏的卡片全文，`lists.tsx` 是搜索，`book.tsx` 是书的阅读界面，`info.tsx` 是接入 AI 说明和版权页，`book.css` 是书的版式。
- `scripts/check-data.mjs`：核对发布包。`scripts/resize-covers.py`：把封面缩到 512×512。`scripts/preview-pages.mjs`：按 GitHub Pages 的子路径预览 `dist`。

## 本地构建

需要 Node.js 22 以上。

```sh
npm ci
npm run check:data
npm run build
```

默认用相对路径构建（`base: "./"`）：同一份 `dist` 放在域名根目录或任意子路径下都能用，数据、封面图、脚本和样式都按相对地址加载。GitHub Pages 的工作流里仍然用 `VITE_BASE_PATH=/game-mechanism-library/` 构建，结果一样可用。按 GitHub Pages 的子路径在本地预览：

```sh
VITE_BASE_PATH=/game-mechanism-library/ npm run preview:pages
# 打开 http://127.0.0.1:4399/game-mechanism-library/
```

推送到 `main` 后由 `.github/workflows/pages.yml` 构建并部署 `dist`。

## 站点配置

`site-config.json` 放在站点根目录（源码里是 `public/site-config.json`），页面每次打开时读取。各字段都可以留空；文件缺失或格式不对时页面按全部留空处理，不会出错。

| 字段 | 作用 |
|---|---|
| `mcp_url` | 公开的 MCP 网址，例如 `https://mcp.example.com/mcp`。填了，“接入 AI”页就给出这个网址的接法；没填显示“即将开放” |
| `mcp_name` | 在 AI 工具里给这个服务起的名字，默认 `game-design-library` |
| `local_download_url` | 本地安装版的下载地址。填了，“接入 AI”页就给出本地安装的步骤；没填显示“即将开放” |
| `contact` | 作者的联系方式（邮箱、网址或一句话）。填了，“版权”页的“请联系作者”后面带上它 |
| `repo_url` | 项目的 GitHub 仓库地址，默认 `https://github.com/mmlong818/game-mechanism-library`。有值时顶栏最右侧显示“GitHub”；没填 `contact` 时版权页引导到这个仓库提 issue。写成空字符串就都不显示 |

## 怎样更新发布包

换发布包不用改代码。

1. 在资料库仓库生成新的发布包（见 CONTRACT.md 第 8 节），得到 `release/<新编号>/` 目录。
2. 把这个目录整个复制到本仓库的 `public/data/release/<新编号>/`。
3. 把 `public/data/current.json` 改成 `{"release":"<新编号>"}`。
4. 旧的发布包目录可以删掉，也可以留着以便回退；留着会一起部署，每个约 13 MB。回退时只需把 `current.json` 改回旧编号。
5. 运行 `npm run check:data`。它会核对：每个库 index 里的 id 都能在对应分组的 cards 文件里找到；所有链接都指向存在的条目；卡片库的每个分组都有封面图；书的每章正文是非空的 markdown，章节序号不重复。
6. 如果新包里有新的分组，给它补一张封面放到 `public/covers/<库>-<分组 slug>.jpg`（可以用 `python scripts/resize-covers.py <封面源目录>` 批量缩图）。
7. `npm run build`，本地预览看一眼，再提交、推送。

发布包的约定大版本变了（1.x 变成 2.0）时，页面会拒绝加载并说明原因，这时需要跟着改 `src/data.ts`。

## 地址

用的是 hash 路由，GitHub Pages 上不需要服务器改写：

| 地址 | 页面 |
|---|---|
| `#/c/<库>/<分组>/<卡片>` | 卡片库的三栏界面，定位到这张卡。库是 `mechanism`、`world`、`experience` |
| `#/`、`#/c/<库>`、`#/c/<库>/<分组>` | 补全成上面的正式地址：没写的部分取第一个分组、第一张卡 |
| `#/e/<库>/<id>` | 旧的详情页地址，换成这张卡的三栏地址 |
| `#/c/book` | 书。库里只有一本书时跳到这本书的第一篇（前言）；有多本时是书单，`#/c/book/<书>` 跳到那本书的第一篇 |
| `#/e/book/<id>` | 章节阅读页（左侧栏加正文） |
| `#/search?q=<词>&c=<库>` | 搜索 |
| `#/mcp` | 接入 AI 说明 |
| `#/license` | 版权。入口只有顶栏最右侧的小字“版权” |

每个页面只有一条浏览路径：导航进库，打开就是三栏，左栏选分组，中栏选卡片，右栏读全文，不用来回跳页。书从导航直接进阅读界面，左栏是全书目录，页尾有上一章、下一章；没有单独的目录页。接入 AI 只从导航进。三栏界面和书的页面不放页脚；署名和更新日期只在搜索页和接入 AI 页的底部，页脚不放链接。

旧版的地址（`#community`、`#favorites`、`m_` 开头的卡片 id 等任何不认识的地址）统一回到首页。专题文章还没有内容，`#/articles` 暂时也回首页，等有文章了再加回导航和首页。旧的 `#/new` 同样回首页。

界面文案是写给访客的：发布包里的 `new`、`thin` 标签网站一律忽略，机制的层级标签（具体机制、机制家族、设计模式）也不显示，所有机制一视同仁；页面上不出现发布编号和卡片 id，页脚只写“更新于某年某月某日”（从发布编号里取日期）。条目按旧 id 访问时会先查发布包里的 `redirects.json`，有去向就跳过去。

## 卡片库的三栏界面

机制、世界观、体验共用一套界面（`browse.tsx`）：

- 左栏 232px：分组（机制是主题），每项是像素封面缩略图、分组名和条数，按条数从多到少排。
- 中栏 280px：当前分组的卡片，只列名称。焦点在中栏时，上下键换到上一张、下一张。
- 右栏占其余宽度：当前卡片的全文，正文一行最多 48 个汉字。

三栏各自滚动，页面本身不滚动。点分组会选中该分组的第一张卡；点卡片只换右栏；点正文里的站内链接（可以跨库）或搜索结果，三栏一起定位到目标卡。每次选择都会改地址，可以分享、刷新，浏览器的后退、前进在看过的卡片之间来回。

宽度不到 1240 时，左栏收成中栏顶部的下拉选择，中栏仍是 280px。不到 860 时只显示右栏，正文上方的“分组和卡片列表”按钮展开列表，选了卡片后自动收起。

进入一个库时加载它的 `index.json`；右栏需要全文时加载该卡所在分组的 `cards/<分组>.json`，加载过的文件都留在内存里。

## 书

书在发布包里是 `kind` 为 `articles` 的库（`collections/book/`）：分组是一本书，条目是一章，`body.text` 是整章的 markdown。书没有封面图，页面上不放图。库里只有一本书时，导航里书这一项直接显示书名；有多本时显示“书”并进书单。

顶栏固定在视口顶部。它的实际高度由 `main.tsx` 写进 CSS 变量 `--top`，固定在视口内的侧栏和标题的停靠位置都按这个变量让出空间。宽度不到 860 时顶栏排成两行：站名、搜索框和“版权”“GitHub”一行，导航一行。

阅读界面是“左侧栏加单栏正文”，版式沿用作者自己那本书的单页版，样式都在 `src/book.css`，只作用于书页：衬线正文（Noto Serif SC）、绛红色强调、浅纸色侧栏。左侧栏宽 264px，固定在顶栏下方、栏内单独滚动，按卷分组，每卷可以折叠（默认全部展开），当前章高亮；前言在最上面，附录在最下面单列一组，栏底是版权行。正文最宽 760px，居中。全书第一篇（前言）上方是书名页（书名、简介、作者，取自发布包），每卷第一章上方是卷名。页尾是上一章、下一章。宽度不到 960 时侧栏回到正文上方，收成可展开的“目录”按钮。深色模式下书页用一套对应的深色值。书页用的字体只在进了书页才从 Google Fonts 加载。

章节正文用 `marked` 转成 HTML。正文里的 HTML 一律当普通文字显示，链接只保留 http、https 和 mailto，所以书稿里即使混进了标签也不会被执行。表格放不下时可以横向滚动；代码块里用制表符画的框图靠 `globals.css` 里几条 `@font-face` 把本机等宽字体的西文缩到半个汉字宽来对齐。

搜索按章节标题、开头一段、书名和正文全文查，结果里标出所属的书。
